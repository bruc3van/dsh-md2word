# Markdown 导出 Word

通过命令执行工具调用 `bruce-md2word`，将 Markdown 转为本地 `.docx`。本 Skill 不依赖 DSH 服务，也不要求 Agent 提供 `word_export` 工具。

## 安装与版本检查

首次使用本 Skill 时先检查 CLI，优先复用已有且符合宿主策略的可用版本，不因存在新版本就自动更新。缺少 CLI 或当前版本无法满足任务时，按下述流程准备环境；遵守宿主的安装审计、执行权限及用户指定的版本、安装位置和离线要求。宿主要求先审后装时，先完成其审计流程；已有授权足够时无需重复询问。

### 1. 检查当前环境

```sh
node --version
bruce-md2word --version
```

当前已验证的运行环境为 Node.js `^24 || ^26`（Node.js 24 与 26，不含 25）。Node.js 缺失或不满足所选版本的要求时，说明需要准备的环境，不反复重装 CLI，也不擅自切换系统默认 Node.js。

- 命令不存在：先检查项目是否已安装该包，避免把不在 PATH 中误判为未安装。
- 项目已有安装时，优先使用 `node "node_modules/bruce-md2word/lib/cli.js" --version`，后续命令也使用同一入口。
- `--version`（简写 `-v`）成功时返回一行版本号。旧版 CLI（如已发布的 `0.3.0`）尚不支持此参数；若报未知选项，先用同一入口的 `--help` 确认可用，再按实际安装位置读取版本，不把未知选项误判为未安装：

  ```sh
  npm list bruce-md2word --depth=0 --json
  npm list -g bruce-md2word --depth=0 --json
  ```

  分别用于项目安装和全局安装，读取 `dependencies["bruce-md2word"].version`。若使用自定义前缀，在查询中也添加相同的 `--prefix`。结合命令的实际路径确认对应安装，不能用全局包版本代替项目版本；包管理器报错也不等于未安装。

### 2. 确定目标版本

用户指定版本、项目已锁定版本或宿主已批准版本时优先沿用，不自动改动依赖和锁文件。已有版本满足任务时直接使用，无需查询 latest。仅在缺少可用版本、用户要求更新或任务需要新版能力时，查询 npm 稳定版作为候选：

```sh
npm view bruce-md2word@latest version engines --json
```

读取 `version` 和 `engines.node`，确认当前 Node.js 满足要求；latest 不代表已经通过宿主审计。按语义版本比较，不能按字符串排序；仅在升级符合用户要求及宿主策略后执行，相同则直接使用，不主动降级或选择预发布版本。

新版不兼容当前 Node.js 时，保留已有可用版本继续转换，并说明更新所需的环境。查询失败或处于离线环境时，已有可用 CLI 也可继续转换并说明未检查更新；没有可用 CLI 时报告实际安装阻塞。用户要求必须使用指定版本时，不以其他版本替代后声称已满足要求。

### 3. 安装或更新

沿用现有包管理器、安装位置及宿主批准的安装方式。仅在允许全局安装且没有其他安装约束时，使用下列命令；更新已有全局安装也可使用同一命令。将 `目标版本` 替换为上一步确认并符合宿主策略的具体版本号，不要原样运行占位符：

```sh
npm install -g bruce-md2word@目标版本
```

已有 pnpm、其他前缀或项目安装时，沿用原来的包管理器和安装位置。项目依赖的升级按用户指定的版本策略执行，不为了追随 latest 擅自改动项目锁定版本。

全局目录无写权限且宿主允许临时安装执行、没有固定安装位置要求时，可以使用 npm 临时执行，无需管理员权限。临时执行同样会下载并运行包，必须遵循相同的审计流程。在项目外的独立临时目录中执行，避免当前项目或上级目录的同名包干扰解析：

```sh
npm exec --yes --package=bruce-md2word@目标版本 -- bruce-md2word --help
```

使用临时执行方式后，后续导出也在该目录保持同一 `--package` 版本前缀，并显式传入源文件绝对路径和 `-o` 输出绝对路径；标准输入中的图片基准目录也使用绝对路径。不假定全局命令已安装，也不通过全局包列表验证临时执行的版本。

安装或更新后，重新检查所选入口的 `--help` 和安装版本，再继续导出。如果命令仍找不到，检查 PATH 或直接使用已安装包的 `lib/cli.js`，不要重复安装；权限、网络或代理错误按实际原因处理，不关闭安全校验或擅改代理设置。

不得为了安装成功而切换包管理器或使用临时执行绕过宿主门禁，也不自行修改 `allowBuilds`、`minimumReleaseAge` 或 `minimumReleaseAgeExclude`。遇到审计、成熟期或构建授权阻塞时，优先使用已有合规版本；没有可用版本则说明具体阻塞，按宿主流程处理。

无需安装 DSH 服务、Office、Python、浏览器或另行执行依赖初始化命令。中文图表需要生成机器有中文字体；实际 Word 分页和字体效果需要另行检查。

## 导出流程

1. 已有 Markdown 时使用原文件；从资料撰写时，先保存为 UTF-8 的 `.md` 文件，保留可修改的源稿。使用用户要求的内容与文件名。
2. 在用户项目目录执行命令，引用含空格或中文的路径。正式交付默认开启严格模式：

   ```sh
   bruce-md2word "docs/报告.md" --strict -o "output/项目报告.docx"
   ```

   省略 `-o` 时保存到当前工作目录的 `output/`。显式输出目录的父目录必须已存在；需要多级目录时先创建目录。文件图片相对源 Markdown 所在目录解析，保持图片位于该目录内；不要为文件输入传 `--asset-base-dir`。

3. 同时检查退出码、stdout 和 stderr。成功退出码为 0，stdout 是 JSON，包含 `protocol`、`path`、`fileName`、`mimeType`、`sizeBytes`、`warnings`。失败为非零退出码，stderr 的 JSON 包含 `error.code` 和 `error.message`；启动失败或包管理器错误可能不是 JSON，保留真实错误。
4. 检查所有警告，按需阅读 [诊断处理](references/diagnostics.md)。严格失败时不擅自关闭严格模式作为最终交付；缺少逐项警告时，可单独生成诊断文档，修正源稿后重新严格导出。相同原因重复失败且没有新修正依据时停止重试，说明需要补充的素材或环境条件。
5. 检查返回路径对应文件存在且非空，交付实际 `path` 和需要关注的警告。同名文件自动编号，不能根据请求的文件名推测最终路径。文件在命令运行机器上；只有宿主提供附件能力时才附加文件，不编造下载链接。

严格成功只表示未检测到内容降级，不代表事实正确或版面验收通过。若未实际打开或渲染文档，明确说明尚未检查分页和视觉效果。

## 输入与能力边界

- 优先文件输入，避免终端管道改变中文编码或解释正文中的 `$`、反引号等字符。必要时可以用 `-` 读取 UTF-8 标准输入，并用 `--asset-base-dir "图片目录"` 指定正文中的相对图片目录；通过执行工具的标准输入传递正文，不将正文拼进 shell 命令。
- 正文、标题、列表、表格保持可编辑，默认中文报告排版。预设、字体/字号/边距覆盖、目录/页码/页眉页脚、标题编号、图表引用及横向分节统一见 [排版说明](../../docs/document-layout.md)；不支持自定义 Word 模板接口。目录和引用须在 Word/WPS 更新域后验收。
- PNG、JPEG、GIF、BMP 图片可嵌入；网络图片不会自动下载，SVG 输入不支持。不要把网络图片或越界路径当作已嵌入成功。
- Mermaid 流程图、状态图、时序图、类图、ER 图、XY 图的常用语法转为 PNG；不覆盖官方全部语法。横向流程图若缩放后文字过小，工具可能保留节点和连线、自动改为纵向布局并返回 `MERMAID_LAYOUT_ADJUSTED` 信息提示。仍过小的宽图应按含义简化或拆分，不能为通过检查随意删除关系。流程图支持节点字号、节点/连线虚线和常用 init/YAML 主题颜色；`MERMAID_STYLE_UNSUPPORTED` 表示部分样式未应用，为信息提示；无法解析的流程图语句会保留源码并报告 `MERMAID_NOT_RENDERED`。
- LaTeX 行内及块公式转为可编辑 Word 原生公式；自定义宏、公式编号与引用等不支持。每次导出最多 1000 个公式，超出时整体返回 `LIMIT_EXCEEDED`（不会降级保存），公式很多的长文档需拆分后分别导出。不支持的公式或图表可能保留源码并产生降级警告。
- 命名脚注转换为 Word 原生脚注，重复引用使用 NOTEREF 域；未定义、重复或嵌套脚注会报告诊断。任意 HTML 和任务复选框仍按普通文本处理，不以严格成功证明版面验收通过。
